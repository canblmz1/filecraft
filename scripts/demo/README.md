# Demo recording

The animation in the main README is recorded from the FileCraft desktop app on Windows. The inputs are synthetic, and the recording can be reproduced with the two scripts in this folder.

| Part | Source |
|---|---|
| Inputs | Generated by `make_inputs.py`: a 4032 × 3024 iPhone-style HEIC with 512 px tiles, Display P3 color and EXIF with a made-up GPS position; a four-page 300 dpi grayscale scan stored as JPEG; and a 20 s portrait iPhone-style MOV with 10-bit HEVC, HLG HDR tags, a rotation flag, AAC audio and a timecode track |
| Inspection, processing and verification | The FileCraft engine in the release build, unchanged, with FFmpeg 8.1 from PATH |
| Native file pickers | Answered by `record_demo.py`, because operating-system dialogs are outside the web view |
| Pointer, captions and title cards | An overlay drawn by `record_demo.py` |
| Encoding | Fast-forwarded and labelled in the video. The result card shows the real elapsed time |

The recorded run reduced 59.92 MB to 4.37 MB under a 5 MB limit in 78 seconds:

- `IMG_4821.HEIC` 7.27 MB → JPEG 1.7 MB at quality 90, RGB PSNR 40.74 dB, EXIF with the GPS position removed
- `signed-forms-scan.pdf` 7.59 MB → 1.2 MB, four page images at up to 200 dpi and JPEG 82, lowest PSNR 42.3 dB, untouched objects decoding identically
- `IMG_4822.MOV` 45.06 MB → H.264/AAC MP4 1.47 MB at 1080 × 1920 and CRF 23, rotation applied and HDR tone-mapped to SDR

The synthetic clip pans across a still image, which encodes far more efficiently than real handheld footage. Expect larger video outputs from real phones.

## Reproduce

Requirements: Windows 10 or 11 with WebView2, Python 3.10+ with `pip install pillow pillow-heif numpy playwright`, FFmpeg 7.1+ with libx265 and FFprobe on PATH, and a release desktop build from `npm run tauri build`. Playwright connects to the app window, so no browser download is needed.

```powershell
python scripts/demo/make_inputs.py C:\FileCraftDemo\phone
python scripts/demo/record_demo.py --app target\release\filecraft-desktop.exe `
  --inputs C:\FileCraftDemo\phone --output C:\FileCraftDemo\results --work C:\FileCraftDemo\work
```

The recorder starts the app with WebView2 remote debugging on local port 9333 and stops it at the end. It types the limit from `--limit-mb` (5 by default) into the goal panel. The output folder must be empty. Use a short, neutral folder because the expanded results show the full output path. The GIF is written to `docs/media/filecraft-demo.gif` and the MP4 to the work folder. To re-render captured frames with different settings, add `--render-only`.
