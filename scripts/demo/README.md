# Demo recording

The animation in the main README is recorded from the FileCraft desktop app on Windows. The inputs are synthetic, and the recording can be reproduced with the two scripts in this folder.

| Part | Source |
|---|---|
| Inputs | Generated by `make_inputs.py`: a procedural 3000 × 2000 PNG landscape, a four-page grayscale "scan" PDF stored without stream compression, and a 24 s 1080 × 1920 H.264/AAC clip at a constant 14 Mbit/s that pans across the same landscape |
| Inspection, processing and verification | The FileCraft engine in the release build, unchanged |
| Native file pickers | Answered by `record_demo.py`, because operating-system dialogs are outside the web view |
| Pointer, captions and title cards | An overlay drawn by `record_demo.py` |
| Encoding | Fast-forwarded and labelled in the video. The result card shows the real elapsed time |

The recorded run reduced 57.41 MB to 9.77 MB under a 20 MB limit:

- `portfolio-photo.png` 6.75 MB → lossless WebP 5.25 MB with identical decoded pixels
- `signed-forms-scan.pdf` 8.42 MB → 255 KB, with changed streams decoding to the original bytes
- `site-visit.mp4` 42.25 MB → 4.27 MB at CRF 23, with a complete decode and a matching frame count

The demo PDF stores its page images without compression, so lossless stream compression saves a lot. Scanned PDFs that already use JPEG or JBIG2 compression will shrink much less, because FileCraft does not downsample scanned pages yet.

## Reproduce

Requirements: Windows 10 or 11 with WebView2, Python 3.10+ with `pip install pillow numpy playwright`, FFmpeg and FFprobe on PATH, and a release desktop build from `npm run tauri build`. Playwright connects to the app window, so no browser download is needed.

```powershell
python scripts/demo/make_inputs.py C:\FileCraftDemo\inputs
python scripts/demo/record_demo.py --app target\release\filecraft-desktop.exe `
  --inputs C:\FileCraftDemo\inputs --output C:\FileCraftDemo\verified --work C:\FileCraftDemo\work
```

The recorder starts the app with WebView2 remote debugging on local port 9333 and stops it at the end. The output folder must be empty. Use a short, neutral folder because the expanded results show the full output path. The GIF is written to `docs/media/filecraft-demo.gif` and the MP4 to the work folder. To re-render captured frames with different settings, add `--render-only`.
