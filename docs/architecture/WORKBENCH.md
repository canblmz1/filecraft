# Workbench architecture

Desktop React calls Tauri commands. A Rust queue limits desktop processing to one job at a time and moves CPU work off the UI thread. SQLite stores pending and terminal job records. Progress is in memory. The CLI and Tauri use the same core. The registry describes built-in raster and PDF adapters, plus optional FFmpeg adapters for MP4 and MOV video and for HEIC photos. The FFmpeg engine can be installed on request into the app data folder; see [dependencies](../development/DEPENDENCIES.md).

1. Preflight checks input signatures and limits, recipe compatibility and output disk space.
2. The worker takes a bounded input snapshot. Each candidate is written and synced in a uniquely named staging directory on the destination volume.
3. Raster candidates are decoded again and checked for dimensions, metadata, ICC profile bytes, alpha and pixel equality or RGB PSNR. HEIC inputs are decoded by FFmpeg, which assembles tile grids and applies rotation, and are checked against the HEIF grid size. Lossless PDF candidates verify page order, parsed objects and trailer, and decompressed bytes of changed streams. Lossy PDF candidates locate each page image through the content stream's transformation matrices to measure its resolution, then verify that every untouched object decodes identically and every re-encoded image is a JPEG of the planned size above the PSNR floor. Video candidates verify codecs, rotation-corrected dimensions, decoded frame count, durations, audio channels and sample rate, relative start offset, and full decode. The report includes byte sizes, SHA-256 and unchecked properties.
4. Begin with the smallest verified candidate for each input. Spend the remaining budget to select higher-fidelity candidates, preferring original bytes if they fit. Photo candidates are ranked by measured RGB error, PDF levels by resolution and JPEG quality, and video rungs by resolution and the encoder's CRF setting, which is a preference rather than a measured quality score. The bounded greedy search does not model perceptual quality.
5. Once the plan meets its limits, publish each verified candidate without replacing existing files. If publication stops after some files, the execution reports partial completion. Output hashes describe the staged bytes at publication. The app does not continuously monitor files afterward.

## Resource and recovery scope

Raster limits are 128 MiB input, 50 megapixels and 20,000 pixels per side. PDF limits are 100 MiB input, 16 MiB per eagerly decompressed PDF stream and 64 MiB per decoded page image. Video limits are 2 GiB input, up to 4096 pixels wide, 180 seconds and 60 average fps, with a three-rung encoder ladder. Cancellation is cooperative in native codecs and stops the active FFmpeg or FFprobe child process. Individual native calls may finish before accepting cancellation.

At startup, the desktop marks unfinished records from the previous session as failed and leaves previously published outputs intact. The OS may leave a staging directory behind after a crash or power loss. A retry creates new output names. Automatic resume, staging recovery, worker OS sandboxing, hard memory or time enforcement, pause, GPU and a full durable retry journal are future work.

Inspection fingerprints identify matching bytes at read time. A known signature and parseable header are not a comprehensive integrity guarantee. File paths are selected by the user and inherit the behavior of the OS, including sync or mounted volumes. SQLite records job outcomes and published output paths in the app data directory. The history view shows up to 100 recent jobs.
